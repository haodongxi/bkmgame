# 联机对战死亡后强制选首发 MVP（2026-08-17）

## 目标

优化联机 PvP 客户端在宝可梦倒下后的操作体验：

- 当当前出战宝可梦倒下时，不再把换人按钮平铺在主操作区
- 改为弹出一个醒目的强制选择弹框，让玩家从剩余可出战宝可梦中选择下一只
- 选择完成后，继续沿用服务端现有回合流转：等待双方都完成换人，再开始下一轮正常速度比较与战斗

## 范围

本次改动 **只限 bkmgame 的联机客户端**：

- 修改目录：`/Users/haodongsheng/git/bkmgame`
- 仅影响 `js/remote.js` 对应的玩家对战界面
- **不修改** 单机战斗界面
- **不修改** `bkmserver`

## 当前问题

当前联机 PvP 在 `pending_switch` 状态下，会把“请选择下一只宝可梦”的按钮直接渲染在战斗底部操作区。

问题在于：

- 不够像“强制处理”的回合阶段
- 和正常出招按钮区域长得太像，容易让玩家漏看
- 在手机竖屏下，操作区容易显得拥挤

## MVP 方案

### 触发条件

当联机对战视图满足以下条件时，客户端自动弹出选择框：

- 当前是 `remote` 联机对战界面
- 服务端返回 `battle.pending_switch` 包含当前玩家 side
- 当前对局尚未结束

### 弹框内容

弹框标题：

- `选择下一只出战宝可梦`

弹框正文：

- 提示当前宝可梦已倒下
- 列出所有仍有 HP、且不是当前倒下宝可梦的队伍成员
- 每只宝可梦显示：
  - 名称
  - 等级
  - 当前 HP / 最大 HP

### 交互规则

- 点击某只宝可梦后，提交现有服务端协议：
  - `POST /api/rooms/{id}/action`
  - body: `{ action: { type: "switch", index } }`
- 提交后关闭弹框
- 主操作区显示“已提交换人，等待对方……”

### 没有剩余宝可梦时

如果没有任何可出战宝可梦：

- 不弹选择列表
- 界面直接等待服务端返回 `battle.over`
- 客户端展示当前已有的败北结果

## 不做的内容

以下内容不进入本次 MVP：

- 修改服务端换人规则
- 修改单机战斗的倒下换人流程
- 增加新的换人动画
- 增加倒下时的全屏遮罩特效
- 把联机对战整体改成独立新界面

## 实现要点

### 1. 保留现有服务端协议

服务端已经通过 `pending_switch` 表达“当前玩家必须换人”，客户端只需要把这个状态改成弹框表现，不需要改协议。

### 2. 主操作区简化

在 `pending_switch` 期间：

- 不再把所有候选宝可梦按钮直接铺在 `#rb-actions`
- 只保留一条状态提示，例如：
  - `请在弹框中选择下一只出战宝可梦`
  - 或 `已提交换人，等待对方……`

### 3. 弹框仅用于联机 PvP

单机对战仍保持原有实现，不复用这个流程。

## 验收标准

### UI

- 联机对战中，我方宝可梦倒下后会自动弹出选择框
- 选择框中只显示可出战宝可梦
- 不再把候选队伍直接渲染在主操作区

### 交互

- 选择一只宝可梦后能正常提交 `switch`
- 提交后主界面提示等待对方
- 当双方都完成换人后，恢复正常战斗指令界面

### 边界

- 若没有剩余宝可梦，不出现无意义的空选择框
- 对局结束后不会残留该弹框
