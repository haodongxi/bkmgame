# 置顶 MVP：PvP 自动握手与取消匹配

Created by haodongsheng

日期：2026-08-18

## 目标

解决玩家快速匹配后退出，另一方进入空房间并等待断线判负的问题。

正常用户无感：匹配到候选对手后，客户端自动完成在线确认，双方确认成功后才进入正式房间。

## 产品规则

- 快速匹配中显示「取消匹配」按钮。
- 服务端找到双方后进入 `pending_handshake`，不立即进入战斗房间。
- 客户端收到服务端握手请求后自动回复，不弹确认框。
- 自动握手窗口为 15 秒。
- 双方都确认在线后，服务端才发送 `room_ready`，客户端才进入正式对战房间。
- 握手期间不启动对战出招倒计时，不记录胜负，不产生战绩。
- 一方退出、取消或 15 秒内未响应，临时握手房间销毁。
- 仍在线且仍在快速匹配状态的另一方自动回到匹配池，不需要重新点击。
- 握手失败时提示「对手连接超时，正在重新匹配……」。
- 连续 3 次握手失败后暂停自动重试，提示用户检查网络。

## 状态机

```text
queued
  → pending_handshake
  → ready
  → battle

pending_handshake
  → handshake_timeout
  → cancelled
  → queued（仍在线的一方）
```

## 推荐协议

服务端匹配成功后发送 `match_probe`，携带 `room_id`、唯一 `request_id` 和 `expires_in=15`。

客户端自动调用：

```http
POST /api/rooms/{room_id}/ready
```

```json
{
  "request_id": "...",
  "status": "online"
}
```

双方确认后服务端发送 `room_ready`。重复请求必须幂等，过期的 `request_id` 不得创建房间。

取消匹配接口：

```http
POST /api/queue/leave
```

取消时应同时清理队列记录和未完成的握手记录。

## UI 提示

- 匹配池：`正在寻找对手……`
- 找到候选：`已找到对手，正在确认连接……`
- 等待确认：`正在连接对手……`
- 握手成功：`对手已连接，正在进入对战……`
- 握手失败：`对手连接超时，正在重新匹配……`
- 用户取消：`已取消匹配`

## 验收标准

- 快速匹配中能看到并使用「取消匹配」。
- 关闭一方页面后，另一方最多等待 15 秒，不进入空房间。
- 双方在线时自动进入同一个正式房间。
- 握手失败不会计入胜负或战绩。
- 取消、超时、重复确认、刷新页面均不会残留旧 `room_id`。
- 单机战斗、单机存档和 PvP 队伍数据不受影响。
